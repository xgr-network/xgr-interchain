# XITA read API, transfer index and verified metrics

This directory implements the read API, finalized transfer projection, untrusted transaction intake, durable proof observer and read-only TVL/flow evidence producer. The earlier assertion that no evidence collector exists is obsolete. Code presence and recorded contracts do not prove production workers are installed or healthy.

From this package directory install declared dependencies (`npm install --ignore-scripts` when no lockfile exists). From repository root start `node services/indexer/server.mjs`, default `127.0.0.1:4088`. The server reads a SELECT-only database role and bounded fresh local evidence. Unknown coverage/value remains unavailable/null, not zero.

API groups include `/health`, `/api/xeta/v1/transfer/health`, `/transfer/recovery`, `/transfers/wallet`, `/transfers/discovery`, `/transfers/stats`, `/metrics/toplist`, `/visibility`, `/systems/<chain>` and bounded POST `/rpc/read` under the same `/api/xeta/v1` prefix. The full service reference gives exact paths, parameters, outcomes and limits. Recovery prepares unsigned Direct-BLS calldata; it never broadcasts or holds user keys.

`transfer-intake.mjs` is a separate loopback-4089 service with restricted staging INSERT authority. Its POST `/api/xeta/v1/transfers/announce` accepts `{account,sourceChain,txHash}` and returns `REPORTED_UNVERIFIED`. Only the XGR Node-owned multi-chain read index supplies finality-bound source receipts; the SQL projector revalidates them against the immutable XITA route catalog. No foreign-chain scan occurs in XITA.

`node-index-projector.mjs` consumes the opt-in XGR Node index read API and maintains the rebuildable SQL projection, source cursors, delivery status and gas statistics. The independent chain-RPC scanner and Gas-Observer sidecar were removed. `transfer-proof-observer.mjs` uses durable database leases for unsigned proof readiness; it does not execute transfers. `tvl-worker.mjs` reads XGR-native state and finality-pinned foreign escrow snapshots **only via the configured XGR RPC**; it reconciles collateral against the same indexed source evidence and produces metrics/history without chain writes. Do not double count synthetic supply or label hop events unique journeys/TVL. CoinGecko values are third-party market data.

Configure `XITA_XGR_INDEX_RPC_URL` as a trusted node endpoint in the transfer-indexer and TVL environment files. It must serve `xgr_getILNIndexedCoverage`, `xgr_getILNIndexedOperations`, `xgr_getILNIndexedSourceReceipt`, `xgr_getILNIndexedDelivery`, `xgr_getILNIndexedEscrow`, `xgr_getILNIndexedGas` and standard native XGR `eth_*` read methods. Apply additive migrations `019_node_index_projection.sql` and `020_node_index_gas_jobs.sql` alongside existing migrations. Use the separate `.env.example`, `.service.example` and explicit SQL/role installers for each component. Do not give the public read API a sponsor key, validator secret or unrestricted database role. Database migrations include two named 010 files; follow explicit installer dependencies. Unit checks: `node --test services/indexer/*.test.mjs` with this package's declared dependencies available. Do not switch the live XITA worker before the read-only live parity gate `node tools/check-node-indexer-cutover.mjs` succeeds against the fully backfilled Node index and the running SQL projection. See `docs/NODE_INDEXER_CUTOVER.md` for the migration sequence. No installation or production activation is implied by this README.
